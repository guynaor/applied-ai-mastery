Slide 1 — Opening, minutes 10–20

What do you redo on a scrap of paper every month, and always lose?

Today we build it twice: a tiny version in chat, and a real application. The comparison between them is the lesson.

Slide 2 — Shrink it

One user, one problem, at most three actions

User and problem: I split costs with two flatmates every month.

Three actions: add an expense  •  show balances  •  reset.

Forbidden: storing bank details, or moving real money.

Every fourth action costs you a test you will not run — doubly so today, because we build twice.

Slide 3 — The tiny version, minutes 20–35

The cheap, fast one first

Build one self-contained web page for splitting costs between three flatmates. Three actions only: add an expense (who paid, how much, what for), show how much each person owes, and reset. Plain labels, a clear reset button, everything in one file. No login and nothing sent anywhere. If a field is empty or not a number, show a message instead of calculating.

Slide 4 — Getting it out of the tool

An artifact that only runs inside the tool is not yours yet

  1. Download the file, or copy the code into tool.html.
  2. Open it in a browser by double-clicking. It should run with no internet.
  3. If something breaks — usually an external file that did not come down with it.
“Change it so everything is in one file — no external library, no font from the internet, no remote image.”

Slide 9 — What we are not building today

The limit

  • No passwords and no account details
  • No other people's data without their knowing
  • No decisions with financial or medical weight
