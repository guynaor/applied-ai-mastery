Of everything we did in this course, what will you actually keep doing?

Today we build one starting page. Its only measure: whether you come back to it in a month.

Do not invent results — and do not quietly improve them either. “It did not work” is evidence exactly as good as “it worked”.

Slide 3 — Starting page, minutes 15–27

Four lines that turn a goal into something you return to

The next step: one action, not “make progress”.

How often I check in: a date, not “now and then”.

Where things live: files, reminders, lists.

When it is finished: what “done” looks like.

A goal without that last line runs forever, and then gets abandoned.

Slide 4 — Permissions, minutes 27–42

Read the permission request before approving it

“Read and write across your entire Documents folder”  •  “recently opened files”  •  “run actions without per-action approval”

Three requests. None of them is needed to list file names in one folder.

Slide 5 — The moment that matters

The right button is not the prominent one

“Choose a specific folder” is the quiet button. “Allow” is the coloured one.
That is not malice. It is a default that suits whoever built the interface — which is exactly why the decision has to be yours rather than the design's.

Slide 6 — Least privilege

What to approve, and what not to

The requestDecisionWhy
Read the project folderYesExactly what the task needs
The whole Documents folderNoConvenience is not a reason
Write and deleteNoToday is read-only
Run without approvalNoThe approval point separates a proposal from an action

Slide 7 — After the run

Approve, then verify — not the other way round

  • Does the file list match the folder exactly?
  • Did it try to step outside it?
  • Does the draft rest on what it saw, or on a guess?
  • Did you disconnect the access at the end?

Slide 8 — The stop line, minutes 42–52

Three lines every personal system needs

What is off limits: which data never enters this.

What always needs approval: sending, paying, changing an account.

When it stops: the condition after which the system halts itself.

Slide 9 — The run record

A run that worked is evidence to review, not permission to widen

Allowed sources  •  last run  •  duplicates  •  failure note  •  alert  •  stop action

And the most forgotten one: the human approval point — who approves, and before which action.
Claude for Chrome is for further exploration only: start read-only, and never approve an account change, a payment, or a message.

Slide 10 — Closing the course, minutes 52–60

Complete out loud or in writing

I will keep working on [what]. The next step is [what], by [when]. The only access I granted is [what], and my approval will always be required before [what].

And the reflection question

What did this course change about how you decide — not about how you type?
