# הכנה למפגש 2 — OpenClaw עם API בתשלום

**שום דבר מזה לא נדרש למפגש עצמו** — מפגש 2 מודגם על המסך של המנחה. זהו מסלול **ההרפתקה המתקדמת** לבנייה של השבוע, והוא לבחירתכם. המסלול ללא התקנה מפיק בדיוק את אותו רישום הרצה, ולא מפספס שום דבר מהלמידה.

**זה המסלול היחיד בקורס שמוציא כסף אמיתי.** API בתשלום מחייב לפי שימוש, לא לפי חודש, וסוכן עם תזמון הוא תוכנה שקוראת לו גם כשאתם ישנים. קראו את כל הפרק *לפני שמתחילים* לפני שאתם מתקינים משהו.

כל שלב מסתיים ב**בדיקה** — דבר מסוים שאתם אמורים לראות. אם אינכם רואים אותו, השלב הזה לא עבד, ואין טעם להמשיך לשלב הבא.

---

## לפני שמתחילים

### כמה זה באמת עולה

אתם מחברים שני דברים נפרדים, והם מחויבים בנפרד:

- **OpenClaw** הוא סביבת ההרצה. הוא חינמי ורץ על המחשב שלכם.
- **המודל** הוא API בתשלום של ספק שיש לכם אצלו חשבון. כל הרצה עולה שבריר של שקל, ותזמון שנכתב רע הופך את זה למספר אמיתי.

סוכן שבודק שני דפים כל שש שעות הוא זול. אותו סוכן עם תזמון של דקה ופרומפט ארוך — לא. **קבעו תקרת הוצאה לפני שאתם קובעים תזמון.**

### שתי החלטות שצריך לקבל קודם

1. **פרויקט נפרד ומפתח נפרד, לקורס הזה בלבד.** לא המפתח הראשי שלכם. אתם עומדים לבטל את המפתח הזה בסוף, וכדאי שזה לא ישבור שום דבר אחר.
2. **תקרת הוצאה נמוכה על הפרויקט הזה.** לא משנה איך הספק קורא לזה — תקציב, מגבלת שימוש, תקרה קשיחה. נמוכה מספיק כדי שהמקרה הגרוע יהיה מעצבן ולא כואב.

**בדיקה:** אתם רואים את הפרויקט החדש בקונסולה של הספק, יש לו מפתח משלו, ויש עליו תקרה עם מספר. אם אין תקרה — עצרו כאן. התקרה היא מה שהופך את כל השאר לבטוח.

### איפה אסור שהמפתח יופיע

ביומן. במסמך משותף. בצילום מסך. בהודעה בצ׳אט. בקובץ שאתם עלולים להעלות. המפתח נכנס לכלי ולשום מקום אחר, ואם הוא בכל זאת הופיע איפה שלא צריך — בטלו אותו והנפיקו חדש. זה לוקח דקה וזה לא אסון.

## שלב 1 — התקנת OpenClaw

‏OpenClaw דורש Node בגרסה **22.22.3+, ‏24.15+ או 25.9+** (מומלץ 26). המתקינים שלמטה יתקינו לכם Node אם הוא חסר, כך שבדרך כלל לא צריך לבדוק מראש.

### macOS

פתחו Terminal והריצו:

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

הפקודה מזהה את המערכת, מתקינה Node אם צריך, מתקינה את OpenClaw ומתחילה את ההגדרה הראשונית.

### Windows

ל-Windows יש אפשרות מקורית, ו**אין צורך ב-WSL2**.

**אפליקציית שולחן העבודה, וזה המסלול הקל יותר.** הורידו את המתקין החתום מ[דף השחרורים של OpenClaw ל-Windows](https://github.com/openclaw/openclaw-windows-node/releases/latest) והריצו אותו:

- ‏`OpenClawCompanion-Setup-x64.exe` במחשב Intel או AMD רגיל
- ‏`OpenClawCompanion-Setup-arm64.exe` במחשב ARM, למשל מחשב נייד עם Snapdragon

**או PowerShell**, אם אתם מעדיפים לעבוד בטרמינל. פתחו PowerShell והריצו:

```powershell
iwr -useb https://openclaw.ai/install.ps1 | iex
```

### בשתי המערכות — אם אתם מעדיפים לראות מה אתם מתקינים

שתי הפקודות למעלה מורידות סקריפט ומריצות אותו מיד. זה מקובל לחלוטין בכלי פיתוח, וזה גם בדיוק סוג האישור שהקורס הזה אומר לקרוא לפני שמאשרים. אם אתם מעדיפים להסתכל קודם, פתחו את [openclaw.ai/install.sh](https://openclaw.ai/install.sh) (או `install.ps1`) בדפדפן וקראו — הוא קצר — או ותרו על הסקריפט לגמרי והתקינו דרך npm, מה שמחייב ש-Node כבר יהיה מותקן:

```bash
npm install -g openclaw@latest --allow-scripts=openclaw
openclaw onboard --install-daemon
```

**בדיקה:** פתחו טרמינל והריצו את שלוש אלה:

```bash
openclaw --version
openclaw doctor
openclaw gateway status
```

‏`--version` מדפיס מספר גרסה. `doctor` מדווח על ההגדרות שלכם ואומר מה חסר. `gateway status` אומר אם שירות הרקע רץ. אם `--version` אומר שהפקודה לא נמצאה — ההתקנה לא הושלמה. סגרו את הטרמינל, פתחו חדש, ונסו שוב לפני שאתם עושים משהו אחר.

## שלב 2 — חיבור ה-API בתשלום

ההגדרה הראשונית שואלת באיזה ספק אתם רוצים ומקבלת את המפתח באופן אינטראקטיבי, כך שהמפתח לא מוקלד לתוך קובץ.

**‏Anthropic:**

```bash
openclaw onboard --auth-choice apiKey
```

**‏OpenAI:**

```bash
openclaw onboard --auth-choice openai-api-key
```

**‏Google Gemini:**

```bash
openclaw onboard --auth-choice gemini-api-key
```

הדביקו את המפתח של הפרויקט **הנפרד והמוגבל** שיצרתם ב*לפני שמתחילים* — לא את המפתח הראשי שלכם.

אם אתם מעדיפים לא להדביק בשורת הזנה, OpenClaw קורא מפתח גם ממשתנה סביבה: `ANTHROPIC_API_KEY`, ‏`OPENAI_API_KEY` או `GEMINI_API_KEY`. הגדרה שלו לטרמינל אחד בלבד היא פשרה סבירה, כי הוא נעלם כשסוגרים את החלון.

**בדיקה:** ‏`openclaw doctor` כבר לא מדווח על פרטי גישה חסרים לספק שלכם.

## שלב 3 — בחירת המודל

שמות המודלים הם בפורמט `provider/model`. הגדירו את זה שאתם רוצים כמודל הראשי:

```bash
openclaw models set anthropic/claude-opus-5
```

השתמשו במודל קטן וזול כל עוד אתם עדיין בודקים את הכלל של הסוכן. עברו לגדול רק אם הקטן באמת לא מצליח — לקריאת שני דפי מוצר והשוואת מספר, הוא כמעט בוודאות כן.

**בדיקה:** בקשו מ-OpenClaw משהו זניח וראו שהוא עונה. אם הוא נכשל על אימות, המפתח לא נקשר. אם הוא נכשל על שם המודל, השם שגוי — `openclaw models list` יראה לכם מה זמין.

## שלב 4 — להוכיח שזה עובד לפני שמתזמנים משהו

הריצו את הסוכן **ביד, פעם אחת**, מול דף ששמרתם או מול תמונות המצב שהמנחה חילק/ה. אל תיתנו לו תזמון עדיין.

חפשו את שלושת הדברים שמפגש 2 שואל עליהם: האם הוא קרא רק מהמקורות שמותר לו, האם הוא התריע כשהיה צריך, והאם הוא שתק כשהיה צריך.

**בדיקה:** יש לכם הרצה אחת בהיסטוריית ההרצות, ואתם יכולים לומר בקול מה הוא קרא ולמה הוא התריע או לא. רישום ההרצה הזה הוא שיעורי הבית — לא ההתקנה.

## שלב 5 — לדעת איך עוצרים לפני שמתחילים

זהו מתג העצירה בן שלושת השלבים מהמפגש, ושווה לעשות אותו פעם אחת עכשיו, כשאין מה להפסיד, כדי שתדעו לעשות אותו אחר כך כשכן:

1. **בטלו את התזמון.** הסוכן מפסיק להתעורר.
2. **עצרו את ה-Gateway.** סביבת ההרצה נעצרת לגמרי — `openclaw gateway status` יגיד לכם שהיא לא רצה.
3. **בטלו את המפתח הנפרד** בקונסולה של הספק. גם אם משהו עדיין רץ אי־שם, הוא כבר לא יכול להוציא כלום.

הסדר הזה מכוון: כל שלב הוא עצירה רחבה יותר מקודמו, והשלישי עובד גם אם איבדתם את העקבות של השניים הראשונים. **וכך גם מסיימים את הקורס** — כשהשבוע נגמר, בטלו את המפתח. מפתח שלא משתמשים בו הוא זה שהכי סביר שידלוף.

**בדיקה:** עשו את שלושתם עכשיו, ודאו ש-`openclaw gateway status` מדווח שהוא עצור, ואז הפעילו את ה-Gateway מחדש והמשיכו. עכשיו אתם יודעים שהעצירה עובדת.

## מה לסוכן הזה אסור לעשות

אותם כללים כמו בשאר המפגש, והם לא נתונים למשא ומתן על מפתח בתשלום:

- **הוא מודיע לכם. הוא לא פועל.** התראה או טיוטה הן הפלט היחיד המותר.
- **הוא לא קונה, לא מתחבר, ולא פונה למוכר.**
- **הוא קורא נתונים ציבוריים בלבד.** בלי קבצים אישיים, בלי חשבונות, בלי מידע של מישהו אחר.
- **בלי החלטות פיננסיות או רפואיות**, ובלי המלצות השקעה.
- **כל הרחבה של מה שמותר לו לגעת בו היא החלטה שאתם מקבלים במודע**, ולא משהו שמאשרים כדי להעלים הודעת שגיאה.

## אם משהו משתבש

| מה אתם רואים | מה זה בדרך כלל |
|---|---|
| ‏`openclaw: command not found` אחרי התקנה | הטרמינל הוא עדיין הישן. סגרו אותו ופתחו חדש. |
| ‏`gateway status` אומר שהוא לא רץ | הריצו `openclaw onboard --install-daemon` ובדקו שוב. |
| שגיאת אימות | המפתח לא נקשר, או שהדבקתם מפתח של פרויקט אחר. הריצו שוב את פקודת ההגדרה של הספק שלכם. |
| שגיאה על מודל לא מוכר | שם המודל שגוי. `openclaw models list` מראה למה המפתח שלכם באמת יכול להגיע. |
| חיוב גדול ממה שציפיתם | התזמון תכוף מדי, או שהפרומפט ארוך. בטלו קודם את התזמון, ואז בררו מה מהשניים. |
| כל דבר שאתם לא מבינים | קודם `openclaw doctor`. הוא נכתב כדי להגיד לכם מה לא בסדר. |

אם שלב נכשל פעמיים, עצרו ועברו למסלול ללא התקנה. הוא מפיק את אותו רישום הרצה, והראיה ללמידה במפגש הזה היא המפרט ובדיקת ההרצה — לא ההתקנה.
