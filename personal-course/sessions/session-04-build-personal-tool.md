# Session 4 — Build a Small Personal Tool

**Time:** 45–60 minutes  
**Outcome:** Specify, test, and maintain a tiny personal web tool that solves one recurring problem without complex coding.

## Integrated studio flow

1. **Specify — 10 minutes.** Choose a poll, expense splitter, packing checklist, or habit tracker. Define one user, three actions maximum, data stored, privacy boundary, and what the tool will not do.
2. **Inspect and adapt — 15 minutes.** Test the starter before changing it. Use an AI assistant only to explain a small change or draft a simple single-page version; keep scope deliberately small and understand every change before using it.
3. **Test — 12 minutes.** Run normal, blank-input, unexpected-input, reset, and refresh tests. Record expected versus actual behavior; fix one issue at a time.
4. **Permission and maintenance review — 8–15 minutes.** Decide where the file lives, who can access it, and how to remove data. Do not put secrets or private group data into the tool.

## Optional tool and free-access paths

Claude, ChatGPT, or Gemini may help explain the starter or generate a tiny edit. **Claude Desktop** is optional support for working with a local file: inspect the exact folder scope and permissions before connecting anything, grant the minimum access, and disconnect when finished. It is not required. Without a tool, annotate the starter and complete the requirements/test plan with a facilitator.

## Integrated artifact and completion check

Submit the requirements, a working or paper-prototyped tool, five test results, one corrected issue, and a maintenance/privacy note. Confirm no complex coding is expected, no secrets were used, and the tool makes no consequential decision.
