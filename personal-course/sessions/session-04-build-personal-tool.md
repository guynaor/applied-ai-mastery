# Session 4 — Solve a Recurring Problem

**Time:** 45–60 minutes  
**Outcome:** Build and test a tiny self-contained personal web tool for one recurring friction.

## Scenario

You repeatedly lose track of something small: packing, a shared choice, a habit, a simple split, or a checklist. Rather than starting a big software project, you will make one tiny tool that has a clear owner and a deliberately limited job. Do not put secrets, private group data, or consequential decisions into it.

## Sequence

1. **Choose the friction (10 minutes).** Describe one user, one repeated problem, and no more than three actions. State what data the tool may keep and what it must never do.
2. **Make the smallest useful version (15 minutes).** Use **Claude Artifacts** to request a self-contained web page/tool. Ask for plain labels, a reset control, and no logins, integrations, or external data. You may instead adapt the supplied starter or make a paper prototype. Inspect every behaviour before you rely on it.
3. **Test the real interaction (12 minutes).** Run one **normal case** (the expected user action) and one **edge case** (blank, unexpected, or unusually long input). Record expected and actual behaviour; revise one behaviour and retest.
4. **Keep control (8 minutes).** Decide where the tool is stored, who can open it, how data is cleared, and when to stop using it. Share only after you have checked it yourself.

## Integrated artifact

Submit a tested personal tool (or paper prototype) and short test log: problem, allowed actions, normal-case result, edge-case result, one revision, and privacy/maintenance note.
