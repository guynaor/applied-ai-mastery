# Instructor Guide — Mission 5: Constraint-Based Operations Planning

**Recommended duration:** 110 minutes  
**Student role:** Operations Planner  
**Primary outcome:** The student can build a feasible itinerary from hard constraints, preferences, travel assumptions, buffers, costs, and contingencies.

## Before the lesson

Open the mission brief, constraint register, location candidates, itinerary template, calendar-import template, answer key, and rubric. Confirm that every travel estimate has a defined origin and that the recovery blocks are treated as hard constraints.

Do not optimize the itinerary for the student. Prepare to challenge feasibility, not taste.

## Teaching objectives

The student should learn to:

1. distinguish hard constraints from preferences;
2. model travel origin, duration, opening windows, cost, and buffer explicitly;
3. test feasibility before optimizing convenience;
4. create contingencies for uncertain or fragile elements;
5. convert a validated plan into calendar-ready records.

## Lesson plan

### 0–12 min — Define success

Ask: “What makes an itinerary good?” Guide the student from “interesting” toward feasible, safe, affordable, resilient, and aligned with objectives.

### 12–30 min — Classify constraints

Review each constraint and require a hard/preferred classification with rationale. Ask what happens if each hard constraint is violated. Ensure recovery time is not sacrificed to add activities.

### 30–48 min — Map candidate activities

For every candidate, identify zone, opening window, duration, cost, purpose, and travel origin. Require the student to flag information that would need live verification in a real trip.

### 48–72 min — Build the first feasible itinerary

Have the student schedule fixed commitments first, then hard recovery blocks, travel, buffers, and finally preferred activities. Require explicit start and end times rather than vague morning/afternoon labels.

Checkpoint questions:

- Where does this transfer begin?
- Does the opening window still work after travel and buffer?
- Is the cost scope complete?
- What happens if the previous activity overruns?

### 72–90 min — Stress-test the required contingencies

Run the two mandatory scenarios from the mission brief:

1. **Arrival delayed by two hours.** The student must update the first-day plan while preserving every hard constraint, explain what moves or is dropped, and identify which stakeholders or bookings require notification.
2. **A planned site becomes unavailable.** The student must select a valid replacement or remove the activity, recalculate travel and timing, preserve recovery blocks, and explain the decision rule used.

Only after both required scenarios pass may you add optional disruptions such as a delayed meeting, unavailable retailer, weather issue, or cost increase.

### 90–102 min — Build calendar output

Check titles, dates, start/end times, locations, notes, and time-zone assumptions. Explain that calendar export is the final serialization of an already validated plan, not a substitute for planning.

### 102–110 min — Debrief

Ask the student to identify the most fragile part of the itinerary and the earliest warning sign that would trigger each required contingency.

## Likely difficulties and interventions

**Difficulty:** Scheduling attractive activities before fixed constraints.  
**Intervention:** Clear the itinerary and rebuild from hard constraints outward.

**Difficulty:** Omitting travel origin.  
**Intervention:** Require every transfer row to answer “from where?”

**Difficulty:** Treating recovery as optional free time.  
**Intervention:** Revisit the constraint register and consequences.

**Difficulty:** Overpacking the schedule.  
**Intervention:** Require a buffer and a stated drop priority.

**Difficulty:** Writing generic contingencies without recalculating the itinerary.  
**Intervention:** Require updated rows, times, travel, and decision rationale for both mandatory scenarios.

## Discussion prompts

- What is the difference between an efficient schedule and a robust schedule?
- When should uncertainty be represented as a wider buffer versus a contingency?
- Which assumptions should be verified close to departure?
- How should an AI planner communicate that a requested itinerary is infeasible?

## Minimum acceptable evidence of learning

The itinerary satisfies all hard constraints, identifies travel origins, contains realistic buffers and costs, produces consistent calendar rows, and includes validated fallback plans for both:

- a two-hour arrival delay;
- an unavailable planned site.

Each fallback must show the resulting schedule changes and preserve all hard constraints. Additional contingencies are optional extensions, not substitutes.

## Extension

Ask the student to create a second itinerary optimized for a different objective, such as lower cost or lower fatigue, while preserving all hard constraints.

## Fallback plan

If mapping or calendar tools are unavailable, use the supplied travel estimates and produce a fully auditable spreadsheet itinerary plus written and recalculated versions of both required contingency plans.
